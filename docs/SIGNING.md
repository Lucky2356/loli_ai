# Ключ подписи APK

Установленная Лоли обновляется поверх только APK, подписанным тем же ключом. Поэтому ключ — самое ценное в репозитории.

## Где он лежит сейчас
Если секретов нет, `scripts/signing-key.sh` при первом релизе создаёт ключ и сохраняет его в **кэш GitHub Actions** (`loli-signing-key-v1`). Кэш стирается через 7 дней без обращений, поэтому `keep-signing-key.yml` раз в неделю к нему обращается. Проверки на pull request и на ветках ключа **не получают** и подписываются временным debug-ключом.

Если ключа нет ни в кэше, ни в секретах, релиз **упадёт** с понятной ошибкой, а не выпустит APK с другой подписью. Создать новый ключ можно только осознанно: запуск `Release APK` с `new_key=true` (все установки придётся один раз удалить и поставить заново).

## Как перенести ключ в секреты (надёжнее кэша)
Ключ, созданный в кэше, достать из Actions нельзя, поэтому переход на секреты — это **новый ключ** (один раз переустановить Лоли):

1. Создайте ключ у себя на компьютере:
   `keytool -genkeypair -keystore loli.jks -storetype PKCS12 -alias loli -keyalg RSA -keysize 4096 -validity 10000`
2. Закодируйте: `base64 -w0 loli.jks` (macOS: `base64 -i loli.jks`).
3. В репозитории: Settings → Secrets and variables → Actions → New repository secret:
   `LOLI_KEYSTORE_BASE64` (вывод шага 2), `LOLI_KEYSTORE_PASSWORD`, `LOLI_KEY_ALIAS` (`loli`), `LOLI_KEY_PASSWORD`.
4. Храните `loli.jks` и пароли отдельно от репозитория (менеджер паролей, офлайн-копия). Потеряете — обновления перестанут ставиться.

## Если ключ мог утечь
Утечкой считается запуск чужого workflow с доступом к кэшу до версии 2.3.0. Признаков утечки Actions не оставляет. Перевыпуск ключа (шаги выше) закрывает риск ценой одной переустановки.
